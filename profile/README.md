<h2>iPhone 的入口在无线网络详情里</h2>
<p>苹果系统的代理设置比较隐蔽：不在「设置」主菜单里，而要进入当前连接的无线网络详情页，滑到最底部才能看到「配置代理」。</p>
<p>这一项只对当前无线网络生效，换一个网络就要重配。理解这个限制，能省掉很多「昨天还好好的今天不行了」的困惑。</p>

<h2>配置的四步</h2>
<p>第一步，打开设置，进入无线局域网，点当前网络右侧的详情按钮。第二步，滑到最底部，找到配置代理，选择手动。第三步，填入服务器与端口，打开认证开关填账号密码。第四步，点存储保存。</p>
<p>四步里第三步最容易出错：认证开关没打开，填了密码也不生效，表现为认证失败。</p>

<h2>切到蜂窝网络会失效</h2>
<p>这是苹果系统的限制，不是配置问题。系统级代理只对无线生效，切到流量后流量直连，出口变回本地地址。</p>
<p>如果业务需要在蜂窝下也走住宅 IP，只能用支持全局模式的客户端，通过本地虚拟接口接管流量。这类方案配置复杂一些，但对网络类型不敏感。</p>

<h2>全局客户端要注意的两点</h2>
<p>第一，安装后可能需要在设置里手动信任配置描述文件。不信任的话，客户端看起来在运行，实际没有接管流量。</p>
<p>第二，iOS 的后台管理较严格，长时间不用可能被系统挂起。表现是「放着不动一会儿就断」，需要把客户端加入后台刷新白名单。</p>

<h2>配完怎么验证</h2>
<p>打开浏览器访问一个查询出口地址的页面，看显示的地址是不是目标住宅 IP。再看解析归属是否与 IP 同地区。最后打开要用的应用，看是否能正常加载。</p>
<p>三项都过才算配好。只做第一项容易出现「浏览器通了但应用不通」的情况。</p>

<h2>为什么应用会连不上</h2>
<p>部分应用不读取系统代理，只走自己的网络栈。表现是浏览器正常，应用报网络错误。</p>
<p>解决办法是改用全局客户端，或者在应用内单独找代理设置。硬在系统设置里反复调是没用的。</p>

<h2>多账号在 iPhone 上怎么处理</h2>
<p>iOS 的隔离能力有限，没有多配置文件机制。可行做法是一机一号，或者用不同的应用分担（比如网页版和客户端版分开）。</p>
<p>账号超过两个时，建议加设备。硬塞多个账号，最后往往是全部牵连。</p>

<h2>iOS 上最容易白忙一场的两个动作</h2>
<p>一是改完不点保存就直接返回，界面看着像改了，实际没生效。二是装了客户端却忘了在设置里信任描述文件，客户端显示运行中，流量却完全没被接管。两个动作都很小，却占了「配了没用」的大部分原因。</p>
<p>所以配完别急着打开应用，先去浏览器查一次出口地址。这一步十秒钟，能立刻告诉你前面两步到底成没成，省下后面反复试的时间。</p>
<h2>常见问题</h2>
<h3>要不要装证书</h3>
<p>普通代理不需要。要求装根证书的方案会显著降低安全性，日常运营没必要。</p>
<h3>能不能用快捷指令切换</h3>
<p>可以做一些自动化，但代理设置本身不在快捷指令的常规可操作范围内。更换节点还是手动改更快。</p>
<h3>换无线网络要重配吗</h3>
<p>要。系统级代理按网络保存，换网络就是新配置。</p>
<h3>为什么比电脑更容易被要求验证</h3>
<p>手机上报的设备信息更多。把系统语言、时区调到与 IP 地区一致，能减少这类情况。</p>
